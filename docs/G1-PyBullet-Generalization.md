## 2. G1a 健康基线 + 噪声本底（检查点 1 ✅ 干净）
- **引擎能量噪声本底**：无阻尼自由抛体（守恒系统）单步 |ΔE| ≈ **8.3e-4 J/step**（系统性、std~1e-15）；
  累计漂移 0.48%/355步。**审计阈值须 > 此本底**（取 10× = 1e-2 J/step）——类比 Phase3 KSG 噪声预算界。
- **🔴 移植教训**：PyBullet **默认线性阻尼 0.04 会悄悄抽能量**（未关时自由抛体 -24.6% 能量）→ 能量预算须显式扣除引擎阻尼，或测守恒时关阻尼。
- **🔴 调试教训（诚实）**：首版非穿透基线**误报**——忘加地面 → 球落穿地板(z→-8)、而 EC5' 用 2D(x,y) 投影忽略 z → 误判「在墙内」。
  修正：加地面保持**平面运动**（z∈[0.099,0.104]恒定），EC5' 的 2D 投影才有效（平台 v_z≈0 不变量）。**这是我自己的 setup 错、非引擎病理，如实记录。**
- **结果**：修正后健康基线**零误报**——能量审计 🟢（floor 1e-2）、非穿透 🟢（球被墙挡在 x=1.85、引擎穿透≈0）。

## 3. G1b 高速穿模（检查点 2 ✅ 非循环·皇冠）
诱发条件：薄墙(半厚0.02m) + 高速 + 默认无 CCD（不手设故障）。`g1b_tunneling.py`，dt=1/120s：
| 速度 | 单步位移 | 穿过? | **引擎自报穿透** | EC5'点检测 | **EC5'扫掠** |
|---|---|---|---|---|---|
| 50 m/s | 0.42m | 是 | 0.042（部分检到）| 🔴 | 🔴 |
| **200 m/s** | 1.67m | 是 | **0.00（完全漏检）** | **🟢 漏** | **🔴 抓** |
| 400 m/s | 3.33m | 是 | **0.00** | 🟢 漏 | 🔴 抓 |

**🔴 核心结论（非循环）**：200 m/s 时球**真穿墙**且 **PyBullet 自报穿透=0**（引擎离散碰撞**完全漏检**——
这是引擎真实数值病理、非我们手设）。**逐帧点检测也漏**（球单步跳过整面墙、无帧落墙内，与引擎漏检同因＝离散采样）；
**唯 EC5' 扫掠版（线段-vs-墙芯）判红抓到**。即：**我们的审计逻辑抓到了我们没造的引擎的真实病理**。
- **移植发现**：2D 平台 EC5' 是逐帧点检测（2D 低速够用）；真引擎高速穿模**必须扫掠线段检测**（`pb_helpers.ec5prime_swept:188`）。这是泛化中真实发现的精化。

### 5.2 三个诚实判据（INV-E）
1. **是否手设故障/调参硬凑？否。** 穿模/能量注入均只设**诱发条件**（薄墙高速 / e=1），故障由引擎数值产生——
   穿模处**引擎自报穿透=0** 即铁证（引擎自己漏检，不是我们伪造违背状态）。
2. **检出是否依赖手调场景？穿模 200 m/s / e=1 是标准诱发参数**，非为触发而精调到临界；如实记录扫描（50 挡住、200+ 穿、阈值清晰）。
3. **健康是否误报？否（修正 setup 后）。** 噪声本底已刻画（8.3e-4 J/step），阈值取 10×；非穿透需平面运动（已加地面）。首版误报来自我的 setup 错，已如实记录并修正。

### 5.3 信任根边界（诚实 scope out）
- 审计经 **PyBullet API**（getBasePositionAndOrientation/getBaseVelocity）读真值——**若 PyBullet 通过其 API 撒谎**（返回错误真值），审计抓不到。
  与 2D 平台 `get_render_state` 信任根盲区（linchpin q 类）**同源**，同样 out of scope。

### 5.4 论文意义
- **强泛化主张成立（部分）**：框架能在**独立构建的真引擎(PyBullet)的原生病理**（高速穿模、能量注入）上检测自欺，**非循环**——不只我们的玩具。
- **诚实 scoped**：warm-start 幽灵力未干净测出（隔离难）；信任根边界（引擎 API 撒谎）out of scope。
- **真实精化**：EC5' 须扩为**扫掠**才能抓高速穿模；能量预算须显式处理**引擎默认阻尼 + 积分噪声本底**。
